# BackportAPI 包冲突白名单
#
# 为什么需要这份名单：
#   1.7.10 的游戏 jar 是签过名的（Mojang 的 MOJANGCS.SF、Forge 的 FORGE.SF）。
#   JVM 在 ClassLoader.checkCerts() 里要求「同一个包的所有类签名信息一致」，
#   于是 BackportAPI 只要把一个类放进上面这些包，就会在类加载时抛
#       SecurityException: class "..." 's signer information does not match ...
#   这跟 JDK 版本、模组逻辑、混淆都无关，是纯打包问题（见 port-analysis/TEST-REPORT-signature-conflict.md）。
#
# 这份名单记录「已经存在、且已被实测确认会触发」的 19 个类，
# 让 check-packages.sh 只对**新增**冲突报警，而不是每次都红。
# 名单本身不解决问题，它只是护栏：一旦有人再往这些包里加类，构建末尾会提醒。
#
# 格式：<签名方> | <类名> | <说明>
#   签名方 = Mojang（META-INF/MOJANGCS.SF）或 Forge（META-INF/FORGE.SF）
#
# 收紧要领：这里每一条都是「不得不沿用原包名」的代价。
# 如果某天方案 B（包迁移）落地，对应条目应随之删除；脚本会提示「可收紧」。
